## Tasks

### Backend

1. - [ ] **Model: sync metadata fields** — in `app/models/pilot/document.rb`, add `store_accessor :metadata` entries for content fingerprint, last sync failure category, and current refresh phase; add `file_document?`, `markdown_document?`, `syncable?` (web-backed only), `sync_stale?`, and `sync_in_progress?` helpers consistent with the existing `sync_status` enum.
2. - [ ] **Model: citation URL eligibility** — in `app/models/pilot/document.rb`, add a method returning the customer-visible source URL or nil: nil for file-backed documents; require parseable `http(s)` URI with host and no userinfo; resolve the host and require every resolved address to be publicly routable (reject private/loopback/link-local/reserved IPv4 and IPv6, including translation prefixes); rescue DNS/URI failures to nil; exclude paths ending in `.pdf`. Reuse the resolver/blacklist building blocks already used by the app's SSRF filtering.
3. - [ ] **Model: markdown support** — new concern (e.g. `app/models/concerns/pilot_markdown_documentable.rb`) included in `Pilot::Document`: `has_one_attached :markdown_file`, virtual pasted-content accessor, validations (`.md` extension, markdown/plain content type, non-empty content, ≤ 10,000 characters, only one file attachment across pdf/markdown), synthetic `external_link` for markdown rows, immediate `available` status for pasted content.
4. - [ ] **Refresh service** — new `app/services/pilot/documents/refresh_service.rb`: fetch the document's own page through the existing ingestion/fetch stack (Firecrawl single-page scrape when configured, simple page fetch otherwise); classify failures permanent (target gone, access refused, empty body) vs transient (timeout, connection/TLS, server error); on success compute the fingerprint of whitespace-normalized content, compare to stored fingerprint, and either mark the document synced (unchanged) or update content/name/fingerprint (changed); record refresh phase transitions on the document; first refresh with no prior fingerprint records the fingerprint but reports an unchanged/baseline outcome.
5. - [ ] **Failure taxonomy in ingestion** — extend `Custom::Pilot::DocumentIngestionService` (or the fetch layer it delegates to) so fetch results carry a machine-readable failure category plus a permanent/transient classification, instead of today's message-only errors; keep `TransientFetchError` semantics for the transient branch.
6. - [ ] **Refresh job** — new `app/jobs/pilot/documents/refresh_job.rb` (`:low` queue, per-document mutex like `CrawlJob`'s source lock): `retry_on` transient failures with the existing `[30s, 2m, 5m]` backoff schedule then mark failed; discard on permanent failure (service has already marked the document); safety-net rescue marks failed with a generic category and reports once; skip documents that are no longer syncable.
7. - [ ] **Scheduler rework** — in `app/jobs/pilot/documents/sync_scheduler_job.rb`: compute eligibility against each account's configured cadence (daily default, weekly, monthly) using a half-interval due window; keep the three-branch eligibility disjunction (synced past window / failed past window / stuck-syncing past stale timeout) and the `last_sync_attempted_at ASC NULLS FIRST` ordering; keep per-account (50) and global (1000) caps but read them from installation config with the current values as defaults; enqueue `RefreshJob` (not `CrawlJob`) with a per-document random delay drawn from a cadence-scaled window (≤ 4 h daily, ≤ 1 day weekly, ≤ 4 days monthly).
8. - [ ] **Account cadence setting** — add the per-account sync frequency (daily/weekly/monthly, default daily) with an installation-config default override; expose the effective interval to the account. (Storage surface per design open question — resolve before starting this task.)
9. - [ ] **Migrations** — composite index on `pilot_documents (account_id, assistant_id, sync_status, last_synced_at)`; backfill migration marking existing `available` web-backed documents as synced with `last_synced_at = updated_at` (batched `update_all`, no-op down).
10. - [ ] **Controller: manual refresh + markdown + sync state** — in `app/controllers/api/v1/accounts/pilot/documents_controller.rb`: add a member refresh action (web-backed and `available` only, marks syncing, enqueues `RefreshJob`, 202); permit `markdown_file`/`markdown_content` params with the model validations doing the work; add sync-state filters (`stale`, `synced`, `syncing`, `failed`) and a `source` filter (`web`, `pdf`, `markdown`) to index; include cadence (`sync_interval_hours`) in the index payload.
11. - [ ] **Jbuilder payloads** — update the pilot documents index/show jbuilder views to expose `sync_status`, `last_synced_at`, `last_sync_attempted_at`, last failure category, current refresh phase, and source type.
12. - [ ] **Schedule config** — update the `pilot_documents_sync_scheduler_job` comment block in `config/schedule.yml` to describe cadence-aware eligibility and jitter (cron entry itself stays hourly).
