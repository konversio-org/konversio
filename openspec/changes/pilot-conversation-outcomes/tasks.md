## Tasks

### Backend

1. - [ ] **Migration** — create `db/migrate/<timestamp>_create_pilot_conversation_outcomes.rb`: `pilot_conversation_outcomes` table with non-null `account`, `assistant`, `conversation`, `inbox` references (assistant/conversation without tight FK coupling to core tables if that matches existing `pilot_*` table conventions — check `pilot_assistants` migration first); `episode_trigger` string non-null defaulting to the initial trigger; `started_at` non-null, `ended_at` nullable; AI reply facts (`first_ai_reply_at`, `last_ai_reply_at`, `ai_reply_count` default 0); `first_human_reply_at`; `handoff_at` + `handoff_reason_category`; `resolved_at`; `csat_rating` + `csat_received_at`; timestamps. Add partial unique indexes: one open episode per `(account_id, conversation_id)` (`ended_at IS NULL`), one initial episode per `(account_id, conversation_id)`, unique `(account_id, conversation_id, started_at)`; plus reporting indexes on `(account_id, assistant_id, started_at/resolved_at/handoff_at)`.
2. - [ ] **Model** — `app/models/pilot/conversation_outcome.rb` (`Pilot::ConversationOutcome`): associations to account, assistant, conversation, inbox; Konversio-owned handoff reason taxonomy and episode trigger enums (string-backed, validated, nil-allowed for reason until a handoff occurs); validation that assistant/conversation/inbox belong to the same account; `chronological` scope and a `covering(at)` scope implementing the half-open window lookup; associations added on `Account`, `Conversation`, `Inbox`, `Pilot::Assistant` (`has_many :conversation_outcomes`).
3. - [ ] **Recording service** — `app/services/pilot/conversation_outcome_recorder.rb`: the single write path with methods for `record_eligibility(at:)`, `record_reopen(at:)`, `record_handoff(at:, reason_category:)`, `record_resolution(at:)`, `record_human_reply(message:)`, `record_csat(response:)`; all wrapped so any `StandardError` is logged + reported to `ChatwootExceptionTracker` and swallowed; reply-fact snapshot helper recomputing AI reply count/first/last within the episode window at terminal events; human-reply eligibility predicate per spec (public outgoing non-private, human sender or external echo, excluding automation-rule and campaign messages).
4. - [ ] **Lifecycle events** — add event constants to `lib/events/types.rb` (e.g. `pilot.conversation.handed_off`, `pilot.conversation.resolved`) and an emitter (e.g. `Pilot::ConversationEvents` service) whose dispatch is failure-isolated (exception-tracked, never raised into the caller); payload: conversation, assistant, source, reason category (handoff only), timestamp.
5. - [ ] **Listener** — `app/listeners/pilot_outcome_listener.rb` subscribing to: `message_created` (first-human-reply), `conversation_resolved` (resolution), `conversation_updated` where status transitions away from `resolved` (reopen), CSAT message update (rating), and the new Pilot handoff lifecycle event; register it in `app/dispatchers/sync_dispatcher.rb` alongside the existing listeners.
6. - [ ] **Eligibility hook** — call `record_eligibility` at the point Pilot first becomes eligible to respond to a conversation (candidate sites: `app/jobs/pilot/autopilot_inference_job.rb` entry, or the message-template hook path); gate on the `pilot` account feature flag and an attached `Pilot::Inbox`. Confirm the exact hook at implementation time (see design Open Questions).
7. - [ ] **Handoff emission wiring** — emit the handoff lifecycle event from every Pilot handoff path: `Conversation#bot_handoff!` call sites driven by Pilot (autopilot inference handoff branch in `app/jobs/pilot/autopilot_inference_job.rb`, the handoff tool path, inactivity/time-based handoff, quota/usage-limit handoff), each with its source and categorized reason.
8. - [ ] **CSAT wiring** — on CSAT survey response creation/update (see `app/listeners/csat_survey_listener.rb` for the `input_csat` detection pattern), call `record_csat` so rating + receipt time land on the covering episode.
9. - [ ] **Tracking-start watermark** — small service (e.g. `Pilot::OutcomeTrackingHistory`) returning the earliest episode `created_at`, cached in Redis with a short TTL while empty and a long TTL once set; exposed for future reporting endpoints.

### Frontend

10. - [ ] **No UI changes** — this change is backend-only; verify no dashboard/settings regressions and that no user-facing strings are added. (Analytics surfaces consume this data in a separate change.)

### Validation

11. - [ ] **Model spec** — `spec/models/pilot/conversation_outcome_spec.rb`: validations, account-consistency guard, `covering` half-open semantics, partial-unique-index behavior (duplicate open episode rejected).
12. - [ ] **Recorder spec** — `spec/services/pilot/conversation_outcome_recorder_spec.rb`: initial episode idempotency; reopen closes predecessor and opens a new episode attributed to the currently attached assistant; handoff/resolution snapshot reply facts correctly; automation-rule and campaign messages do not set `first_human_reply_at`; externally echoed human replies do; errors are swallowed and exception-tracked.
13. - [ ] **Listener spec** — `spec/listeners/pilot_outcome_listener_spec.rb`: each subscribed event routes to the correct recorder call; events on accounts without the `pilot` feature are ignored.
14. - [ ] **Integration check** — end-to-end on a dev seed: conversation with an attached assistant → AI replies → handoff with a category → human reply → resolution → reopen → CSAT; assert the episode stream reflects every step.

## Dependencies / Order

Tasks 1 → 2 → 3 are sequential (table, model, recorder). Task 4 (events) and task 5 (listener) depend on 3. Tasks 6–8 wire emission/consumption and depend on 4–5; they are independent of each other. Task 9 is independent and can land any time after 1. Tasks 11–13 follow their respective implementation tasks; task 14 validates the whole chain last.
