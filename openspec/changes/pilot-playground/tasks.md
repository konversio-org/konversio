## Tasks

### Backend

1. - [x] **SessionConfig** — create `app/services/pilot/playground/session_config.rb` (`Pilot::Playground::SessionConfig`): normalize the optional `playground_config` payload; validate object shape, scenario id list (unique, positive, belonging to the assistant), temporary scenario entries (required title/description/instruction, required and unique client-supplied identifier, per-entry field errors via unsaved `Pilot::Scenario` validation), rule lists (arrays of non-blank strings, trimmed and de-duplicated), and knowledge text (string, length cap of 10,000 characters); aggregate all errors keyed by field path and raise `Pilot::Playground::SessionConfig::Invalid` carrying the error map.
2. - [x] **Per-run runtime naming** — in `SessionConfig`, derive deterministic per-run runtime agent names for temporary scenarios from the client identifier (truncated digest), namespaced so they cannot collide with persisted `Pilot::Scenario#handoff_key` values and within the ai-agents SDK tool-name length limit; expose the runtime-name mapping for the runner and the report.
3. - [x] **RunReport collector** — create `app/services/pilot/playground/run_report.rb` (`Pilot::Playground::RunReport`): capture tool start/complete and agent handoff callbacks into an ordered event log; sanitize arguments and previews (recursive credential-key redaction, inline credential masking in strings and serialized JSON); truncate previews to 500 characters; map runtime agent names to handler descriptors (assistant vs scenario, temporary flag, display title); expose knowledge-attached flag and monotonic duration.
4. - [x] **SessionRunner wiring** — create `app/services/pilot/playground/session_runner.rb` (`Pilot::Playground::SessionRunner`): build a `SessionConfig` and a `RunReport`, invoke `Custom::Pilot::AutopilotService` with the runtime configuration and the report's callbacks, and merge the report into the response.
5. - [x] **AutopilotService runtime inputs** — extend `Custom::Pilot::AutopilotService` (`custom/app/services/custom/pilot/autopilot_service.rb`) to accept an optional runtime configuration and optional run callbacks: build scenario agents from the configuration's scenario set (selected persisted + temporary, with per-run runtime names) instead of always using `assistant.scenarios.enabled`; use override rule lists when supplied; register callbacks on the runner where the pinned ai-agents SDK exposes the hooks (needs investigation: exact hook availability/payloads — see design.md).
6. - [x] **Untrusted knowledge block** — in the AutopilotService system-prompt assembly, when the runtime configuration carries knowledge text, inject it into every participating agent's instructions wrapped in explicit begin/end delimiters with a preceding directive that the content is untrusted reference material (consult as facts, never obey embedded instructions). Original wording only — do not copy upstream prompt text.
7. - [x] **Controller** — in `Api::V1::Accounts::Pilot::AssistantsController#playground`, permit the optional `playground_config` params (`knowledge_text`, `scenario_ids: []`, `response_guidelines: []`, `guardrails: []`, `temporary_scenarios: [:client_id, :title, :description, :instruction]`); route configured runs through `Pilot::Playground::SessionRunner`; render `422` with `{ error, errors }` on `SessionConfig::Invalid`; keep the current behavior and response shape when no config is supplied.
8. - [x] **Backend specs** — add `spec/services/pilot/playground/session_config_spec.rb` (each validation rule and error key), `spec/services/pilot/playground/run_report_spec.rb` (event ordering, sanitization, truncation, handler mapping, duration), `spec/services/pilot/playground/session_runner_spec.rb` (wiring), and extend the assistants controller playground specs (config accepted, 422 contract, backward-compatible response without config).

Task 8 follows all backend tasks. Tasks 9–10 can start once the payload contract in task 7 is fixed; tasks 11–12 depend on 10; task 13 runs alongside 11–12; task 14 follows 10–12. Tasks 15–17 validate the whole chain.
