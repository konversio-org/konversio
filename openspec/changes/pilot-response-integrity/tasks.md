## Tasks

### Backend

1. - [x] **Length budget service** — add `lib/pilot/reply_length_budget.rb` (`Pilot::ReplyLengthBudget`): given a conversation, resolve the character budget with this precedence — (1) Instagram direct-message conversations (conversation `additional_attributes['type']`) → 1,000; (2) Twilio inboxes by `channel.medium` → 320 for SMS, 1,600 for WhatsApp; (3) per channel type — Facebook 2,000, Instagram 1,000, LINE 5,000, SMS 320, Telegram 4,096, TikTok 6,000, WhatsApp 4,096; (4) all other channels → 10,000. Return nil for a nil conversation.
2. - [x] **Budget disclosure in prompt** — in `Custom::Pilot::AutopilotService#assistant_instructions`, when a budget resolves for the conversation, add a freshly worded section telling the model the reply must stay within N characters to be deliverable on this channel. No section when no budget applies (playground runs without a conversation).
3. - [x] **Structured reply contract in the runner** — extend `Custom::Pilot::AutopilotService` so that, when the assistant's citation config is enabled, the assistant agent runs with a structured output contract: a reasoning field plus an ordered, non-empty list of parts, each part a non-empty text field and a list of positive-integer source indexes (possibly empty). Reuse the `lib/pilot/structured_reply.rb` value object from `pilot-agent-sessions-and-citations` for parsing/normalization/degradation; keep `extract_reply` semantics for the plain path. Ensure sentinel parsing (handoff/resolution) runs on the assembled plain text and sentinels are stripped from part text before delivery.
4. - [x] **Reply shortener service** — add `lib/pilot/reply_shortener.rb` (`Pilot::ReplyShortener`): given the run result and a text-only budget (budget minus citation-markup length), run a single-turn, temperature-0 agent run whose freshly worded instruction asks to shorten each part's text to fit, preserving part count, order, facts (names, numbers, dates, links, warnings, completed actions), valid markdown, and citation assignment. Programmatically verify the result: identical part count and, when citations are enabled, identical per-part citation indexes (then re-attach original citations regardless); any violation raises. Replace the final assistant output in the run's history/messages with the shortened output.
5. - [x] **Rewrite-or-fail enforcement** — in `Custom::Pilot::AutopilotService` (post-generation, pre-delivery): assemble the rendered customer message (parts + resolved citation links); if it exceeds the budget, compute the text-only budget and fail immediately unless it is positive (citation markup alone must not exceed the budget); invoke `Pilot::ReplyShortener` once; re-measure; if still over budget, raise so the error path hands off. Only run when a budget applies.
6. - [x] **Consent protocol in instructions** — rewrite the escalation/consent sections of `Custom::Pilot::AutopilotService#assistant_instructions` (fresh wording, no upstream text) to require: handoff execution only after an explicit customer request for a human, an accepted offer, or a guideline/guardrail-mandated transfer; offers only when the customer is blocked, repeats the request, rejects clarification, or the issue needs capabilities/permissions the assistant lacks; never claim a transfer unless the handoff mechanism executed; no re-offers while a handoff is pending (existing `handoff_already_requested?` state); no promises of work after the reply is sent unless the action is completed in-turn via a tool.
7. - [x] **Promise guard setting** — add boolean account setting `pilot_false_promise_guard_enabled` via `store_accessor` in `app/models/account.rb` and whitelist it (`'type': %w[boolean null]`) in `app/models/concerns/account_settings_schema.rb`.
8. - [x] **Promise detector service** — add `lib/pilot/promise_guard.rb` (`Pilot::PromiseGuard`): a deterministic (temperature 0) structured-output detector that, given the conversation context and the draft reply, returns exactly one of two verdicts — safe to deliver, or unsupported future-work promise — plus a categorized reason from a fixed implementation-side taxonomy and the model used. Detector errors or unusable output return an inconclusive result (never raise). Resolve the detector model via Konversio's `Llm::Config`/`model_for` resolution (see design.md needs-investigation).
9. - [x] **Guard wiring with fail-safe handoff** — in `Pilot::AutopilotInferenceJob` (or the delivery step of `AutopilotService`): when the account setting is on and the run did not already request a handoff, run the detector on the final reply text. On a promise verdict: regenerate the reply once via the autopilot pipeline with the draft appended to the context and a freshly worded internal repair instruction (may use tools; must answer from what is verifiable now, ask one concrete clarifying question, or offer a handoff without claiming it happened); re-run the detector; if still not verifiably safe — or if the guard errors after a detection fired — suppress the reply and execute the handoff via `Custom::Pilot::HandoffService` with a categorized reason identifying the guard. Inconclusive first-pass results deliver the original reply. Log every detection (verdict, reason, model, account, conversation) and wrap the whole guard so it never raises into delivery.
10. - [x] **Handoff reason surfacing** — when the guard forces a handoff, record the categorized reason on the handoff path (handoff event/log and, if product agrees, a private note on the conversation — see design.md open question) so operators can distinguish guard-triggered handoffs from customer-requested ones.
11. - [x] **Turn budget hardening** — in `Custom::Pilot::AutopilotService`: keep `PILOT_AUTOPILOT_MAX_TURNS` (default 6, MUST NOT exceed 10); confirm non-positive/unparsable values fall back to the default; investigate how the ai-agents runner signals turn-budget exhaustion and wire it explicitly to the run-failure path so a partial answer is never delivered (error path → `handoff_on_error` in `Pilot::AutopilotInferenceJob`).
