## Tasks

### Backend

1. - [x] **Reporting window service** — add `app/services/pilot/analytics/reporting_window.rb` (`Pilot::Analytics::ReportingWindow`): accept `range` (day counts `7`/`30`/`90`, named periods this/last week, this/last month; unknown values fall back to `7`) and `timezone_offset` (viewer UTC offset in hours, mirroring the reports API); resolve the current window and a mirrored previous window anchored to the viewer's timezone; clamp the comparison window at the previous month's end for month periods; expose a timezone-validity flag and a human-readable period descriptor (label + start/end dates).
2. - [x] **Outcome classifications** — add `app/services/pilot/analytics/outcome_classifications.rb`: shared query-time predicates over `pilot_conversation_outcomes` for *involved* (AI replied, or handed off for any reason other than pre-participation quota exhaustion), *autonomous* (resolved, AI replied, no handoff, no human public reply before resolution), *assisted* (involved and resolved but not autonomous), *handoff* (involved with a handoff timestamp), *reopened autonomous*, and *durable* (no reopen within the seven-day durability window).
3. - [x] **Tracking history** — add `app/services/pilot/analytics/tracking_history.rb`: earliest `pilot_conversation_outcomes.created_at` across the installation, cached via `Redis::Alfred` with a long TTL once present and a short TTL while empty.
4. - [x] **Overview report** — add `app/services/pilot/analytics/overview_report.rb`: compute the full metric set (conversations involved, autonomous resolutions + rate, handoff count + rate, estimated hours saved, reopen-after-resolution rate, conversation depth, durable resolution rate, autonomous/assisted/human-only CSAT, median resolution seconds) for both windows, batching per-window aggregates into single scans with conditional aggregation; pack each metric as `{ current, previous, trend }` with percent/point/absolute trend modes and null-for-untracked semantics.
5. - [x] **Resolution flow report** — add `app/services/pilot/analytics/resolution_flow_report.rb`: balanced three-way split of the involved cohort plus the stayed-closed/reopened split of autonomous resolutions, and the categorized handoff-reason distribution (count + percentage, uncategorized bucket, sorted by count); return empty nodes/links for untracked periods.
6. - [x] **Resolution trend report** — add `app/services/pilot/analytics/resolution_trend_report.rb`: bucket the current window by day (windows up to 15 days) or by week (Sunday start) in the viewer's timezone; build comparison buckets by shifting whole calendar weeks; per bucket return involved count, autonomous count, current resolution rate, and previous-period rate (null when the comparison precedes tracking start); single outcome-table scan via conditional aggregation.
7. - [x] **Drilldown query** — add `app/services/pilot/analytics/drilldown_query.rb`: supported-metric guard (conversations involved, auto-resolution rate, handoff rate, reopen-after-resolution rate), cohort queries matching the card aggregates (see design.md), pagination (default page 1, default 25 per page, max 100), response meta (metric, page, per page, total count, window since/until as epoch seconds), records serialized with `V2::Reports::DrilldownRecordSerializer` from the `reporting-drilldowns` change.
8. - [x] **Summary generator** — add `app/services/pilot/analytics/overview_summary_generator.rb` (< `Pilot::BaseTaskService`): build the structured report payload (period descriptor, overview metrics, resolution flow, resolution trend), return an empty point list without an LLM call when there is no activity, call the model with a structured-output schema bounded to at most three short observation strings, and strip/blank-filter the returned points.
9. - [x] **Summary prompt** — author a new original prompt template under `lib/pilot/prompts/` (Liquid, matching existing Pilot prompt conventions): supply the assistant name, the account's language, and the pretty-printed structured report; instruct the model to surface the most decision-useful observations for a support lead, grounded only in the supplied numbers. Original wording only — do not adapt any upstream prompt text.
10. - [x] **Analytics controller** — add `app/controllers/api/v1/accounts/pilot/assistant_analytics_controller.rb` with `overview`, `resolution_flow`, `resolution_trend`, and `overview_summary` actions; authorize read access via `Pilot::AssistantPolicy` for all account users; validate the timezone offset on `overview_summary` (422 when invalid); cache successful summary results in `Redis::Alfred` under a versioned key (account id, assistant cache version, resolved range, timezone, tracking start, account locale) with a one-hour TTL; never cache failures (render 422); merge the tracking-start timestamp into the overview response.
11. - [x] **Drilldown endpoint** — add a `drilldown` member action to `Api::V1::Accounts::Pilot::AssistantsController` returning 422 for unsupported metrics and delegating to the drilldown query; enforce administrator-only access in `app/policies/pilot/assistant_policy.rb` (new policy methods for analytics read vs drilldown).
12. - [x] **Routes** — register the analytics endpoints under the existing `namespace :pilot` → `resources :assistants` block in `config/routes.rb` (nested stats-style resource for the four analytics actions; member `get :drilldown`).
