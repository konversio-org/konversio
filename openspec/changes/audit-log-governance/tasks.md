## Tasks

### Backend

1. - [ ] **Migration: geo columns** — add nullable `city`, `country`, `country_code` string columns to the `audits` table.
2. - [ ] **Migration: listing index** — add index `index_audits_on_associated_and_created_at` on `audits (associated_type, associated_id, created_at)` with `algorithm: :concurrently`, `if_not_exists: true`, and `disable_ddl_transaction!`.
3. - [ ] **AuditLog model** — create `app/models/audit_log.rb` (`AuditLog < Audited::Audit`); re-enable `config.audit_class = 'AuditLog'` in `config/initializers/audited.rb`. Implement: after-save denormalization of actor email into `username` and account association for account-level entries; query scopes for auditable types, created-after/created-before, and actor search (escaped case-insensitive match on `username` or the linked user's name/email, users joined only when `user_type` is `User`); `location` (city + country joined, blank parts dropped); `masked_remote_address` (IPv4 last-octet placeholder, IPv6 truncated after four hextets, null on blank/unparseable); `resolve_ip_location!` via `IpLookupService`, gated on the account's `ip_lookup` flag, writing with `update_columns`; after-create-commit enqueue of the per-entry geo job when an address is present and lookup is enabled.
4. - [ ] **Account association** — add the account-scoped audit association (e.g. `has_many :associated_audits`) to `Account` so listing queries stay account-local.
5. - [ ] **Recording: governed models** — add `audited` declarations / audit callbacks for `Account` (settings updates), `AccountUser` (invite/role changes), `Inbox` (create/update), `Webhook` (excluding secrets), `AutomationRule`, `Macro`, `Team`, team membership and inbox membership changes (create/remove), and `Conversation` (deletion only, no attribute payload).
6. - [ ] **Recording: sign-in/sign-out** — in `DeviseOverrides::SessionsController`, on successful sign-in and on sign-out, bulk-insert one audit entry per account the user belongs to (actor email, request IP from the audited request store, request UUID, monotonically increasing version per user), then enqueue the batched geo job; wrap enqueueing so auth can never fail because of audit/job errors.
7. - [ ] **Recording: message deletion** — in `Api::V1::Accounts::Conversations::MessagesController#destroy`, take a row lock on the message, skip audit if already soft-deleted, snapshot deletion context (conversation id + display number, inbox id, sender type/id, original body) before the soft delete, perform the soft delete, then create the `destroy` audit entry with the acting user, account association, and request IP — all inside the lock.
8. - [ ] **Listing controller** — create `app/controllers/api/v1/accounts/audit_logs_controller.rb` backing the existing `resource :audit_logs, only: [:show]` route (`config/routes.rb:98`): admin-only; empty result (plus a warning log) when the account's `audit_logs` flag is off; apply types/search/date-window filters and `created_at` sort; paginate at 25 per page; epoch params validated against the DB-representable range, invalid values ignored.
9. - [ ] **Listing view** — create `app/views/api/v1/accounts/audit_logs/show.json.jbuilder`: serialize pagination meta (`per_page`, `current_page`, `total_entries`) and entries; for message entries serve `auditable: null` and strip the body key from `audited_changes`; serve full `remote_address` only when the account's `audit_log_ip_address` flag is on, otherwise masked address plus `location` when resolved.
10. - [ ] **Feature flags** — add `audit_log_ip_address` (default off) to `config/features.yml` and a matching entry in `app/helpers/super_admin/features.yml`; confirm `Featurable` generates the `feature_audit_log_ip_address` scope/accessors without any column migration. needs investigation: decide whether the existing `audit_logs` flag keeps its `premium: true` marker / default-off state for self-hosted Konversio.
11. - [ ] **Geo jobs** — create `app/jobs/audit_log_ip_lookup_job.rb` (single entry, discard on deserialization error), `app/jobs/audit_log_session_ip_lookup_job.rb` (one lookup, bulk-update the sign-in batch, account `ip_lookup` gate), and `app/jobs/audit_log_ip_location_backfill_job.rb` (id-cursor batches of 500, short delay between self-reschedules, low queue, skips/fails logged per row); all rescue and log rather than raise.
12. - [ ] **Rake task** — `lib/tasks/audit_log.rake` with `audit_log:backfill_ip_location` enqueuing the backfill job for operator-triggered backfills.
13. - [ ] **Swagger** — update `swagger/definitions/resource/audit_log.yml` (nullable `auditable`, masked-vs-full `remote_address`, `location`) and `swagger/paths/application/audit_logs/index.yml` (new query params, 25 per page).

## Dependencies / Order

Tasks 1–3 (schema + model) are the foundation and must land first, in order. Task 4 unlocks 8–9. Tasks 5–7 (recording) depend on 3 and can run in parallel with each other. Task 10 must precede 9 (view branches on the flag) and 11 (jobs gate on flags). Tasks 11–12 depend on 3. Task 13 can run any time after 8–9. Frontend tasks 14–16 can start in parallel with backend; 17–18 depend on 16 and are easiest to verify against a working 8–9; 19–20 are independent. Validation tasks 21–25 follow their respective implementation tasks; 26 is last.
