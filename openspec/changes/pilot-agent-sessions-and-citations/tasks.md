## Tasks

### Backend

1. - [x] **Migration** — create `pilot_agent_sessions` table: session kind (integer, not null), polymorphic `subject` (not null, no direct index), polymorphic `result` (nullable, no direct index), `account` reference (not null), `assistant` reference (not null), nullable `user` reference, `llm_model` string, nullable numeric usage-charge column (only if the investigation in design.md finds a real per-run usage metric — otherwise omit), JSONB array columns for offered FAQ ids, used FAQ ids, consulted document ids, cited document ids, and participating scenario ids (all default `[]`, cited/used FAQ ids `null: false`), JSONB `run_context` (default `{}`), timestamps. Indexes: `account_id`; `assistant_id`; `user_id`; composite `(account_id, session kind, created_at)`; composite `(account_id, subject_type, subject_id)`; composite `(account_id, result_type, result_id)`; GIN indexes on consulted document ids, cited document ids, and used FAQ ids (concurrently, transaction disabled).
2. - [x] **Model** — add `Pilot::AgentSession` (`app/models/pilot/agent_session.rb`): session kind enum (autopilot / copilot, prefixed); associations to `account`, `assistant` (`Pilot::Assistant`), optional `user`, polymorphic `subject` and optional polymorphic `result` (both account-scoped); validations that subject/result types match the session kind and that subject/result belong to the session's account; derive `account` from the assistant before validation; a scope for sessions with a delivered (charged) answer if the usage column exists.
3. - [x] **Associations** — add `has_many :pilot_agent_sessions` (dependent destroy-async) to `Account` and `Pilot::Assistant`.
4. - [x] **Customer-visible source URL contract** — add to `Pilot::Document` a method returning a customer-resolvable source URL only when the document is flagged customer-visible, its external link is a well-formed `http(s)` URI, and the link does not point at an uploaded PDF (uploaded files carry no customer-resolvable link); return nil otherwise (including on malformed URIs). Expose the equivalent through `Pilot::AssistantResponse` when the response belongs to a document.
5. - [x] **Trusted citation resolution on `Pilot::Assistant`** — add a method that takes the run's index→document-id mapping and returns index→URL for eligible entries only (per task 4's contract), gated on the assistant's citation config; add a convenience that extracts the mapping from a run result's state.
6. - [x] **Structured reply value object** — add a value object under `lib/pilot/` (e.g. `lib/pilot/structured_reply.rb`) that: parses a raw model response into an ordered list of parts (each `text` + positive-integer citation indexes, deduplicated, blank parts dropped); degrades any non-structured or string response to a single citation-free part; joins parts into plain text; renders customer-facing content by appending numbered markdown links per part (numbers assigned per unique URL in first-appearance order, reused on repeats, URLs markdown-escaped for parentheses, links placed on a new line when the part ends with a code fence); and can produce a citation-stripped copy.
7. - [x] **Generation prompt** — extend the Pilot generation prompt assembly so that, when the assistant's citation config is enabled, the model is instructed (in freshly written Konversio wording) to reply as structured parts with source indexes drawn only from the indexes shown in knowledge results, and is forbidden from placing source URLs in reply text or citation fields. When citations are disabled, the prompt and response format stay as today.
8. - [x] **Autopilot pipeline wiring** — in `Custom::Pilot::AutopilotService` / `Pilot::AutopilotInferenceJob` (`app/jobs/pilot/autopilot_inference_job.rb`): keep the run's index→source mapping in run state; build outgoing message content from the structured reply resolved with trusted citation URLs; store the structured parts on the message's `additional_attributes`; after delivery, invoke the capture service. On handoff runs, link the session to the private handoff note when the run recorded one.
9. - [x] **Session capture service** — add a capture service under `lib/pilot/` (e.g. `lib/pilot/agent_session_recorder.rb`) that creates the session from assistant, conversation, run result, result message, and usage (if available): skip when the run was not successful; wrap all failures (log + exception tracker, never raise); compute cited document ids as the intersection of indexes used in the delivered parts and indexes with eligible trusted URLs; collect participating scenario ids from the turn's assistant-role entries and intersect with the assistant's own scenarios; store turn-scoped run context (latest customer message onward, rich content normalized to serializable form).
10. - [x] **Copilot capture (may ship second)** — invoke the same capture service from the copilot reply path with thread/message as subject/result, where structured replies are supported there.
11. - [x] **Session detail endpoint** — add `show` under the account-scoped `pilot` namespace in `config/routes.rb` (member-style, addressed by message ID) with a controller at `app/controllers/api/v1/accounts/pilot/agent_sessions_controller.rb`: find the account's message by ID, authorize conversation visibility via the existing conversation policy, find the session whose result is that message, return 404 otherwise; respond (Jbuilder under `app/views/api/v1/accounts/pilot/agent_sessions/`) with session id, message id, model, usage (if present), run context (as an array), cited sources (id, title, link only when `http(s)`), used FAQs (approved, user-authored only; id and question), and participating scenarios (id and title).

### Frontend

12. - [x] **API client + store** — add `app/javascript/dashboard/api/pilot/agentSessions.js` and a namespaced store module caching session detail per message id; cache 404s as "no session" except for very recent messages (the session may not be written yet — retry on next hover/click); never cache transient (5xx/network) failures.
13. - [x] **Inspection UI** — add a `components-next/message/` affordance on AI-authored messages (Pilot variant, gated on the Pilot feature flag) that opens a popover/panel with: knowledge sources used (cited documents with links + used FAQs), a humanized steps timeline of the run (tool calls with arguments and scenario hops — no message bodies, no raw tool output), and graceful empty/loading states. English i18n only (`en.json`).
