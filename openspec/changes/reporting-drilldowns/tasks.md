## Tasks

### Backend

1. - [ ] **Metric registry** — create `app/services/reports/report_metric_registry.rb` (`Reports::ReportMetricRegistry`) describing each public metric: API name, aggregate type (`:count`/`:average`), raw `reporting_events` name, and raw count strategy (`:exclude_bot_handoffs` for bot resolutions, `:distinct_conversation` for bot handoffs). Port from upstream v4.18.0 (MIT), keeping only what the drilldown consumes. needs investigation: coordinate with the reports-refactor change if one is planned, so the registry is not defined twice.
2. - [ ] **Timestamp validator** — create `app/services/reports/drilldown_timestamp_validator.rb` (`Reports::DrilldownTimestampValidator`): integer-only `bucket_timestamp`/`since`/`until`, `since < until`, bucket window overlaps the requested range in the request timezone. Port from upstream v4.18.0 (MIT).
3. - [ ] **Drilldown builder** — create `app/builders/v2/reports/drilldown_builder.rb` (`V2::Reports::DrilldownBuilder`): resolve dimension scope (account/inbox/agent/label/team via `params[:id]`), intersect bucket window with `[since, until]`, dispatch per metric type (conversations / messages / reporting events with count strategies), paginate (`page` ≥ 1, `per_page` default 25, max 100), and compute `meta` including distinct `conversation_count`. Port from upstream v4.18.0 (MIT).
4. - [ ] **Record serializer** — create `app/builders/v2/reports/drilldown_record_serializer.rb` (`V2::Reports::DrilldownRecordSerializer`): conversation/message row shapes, `metric_value` honoring `business_hours`, `occurred_at` from event end time, batch latest-message preview via `DISTINCT ON (conversation_id)`, and message inference for first-response/reply-time events (outgoing/template message within ±1s of event end; sender match for user-attributed first responses). Port from upstream v4.18.0 (MIT).
5. - [ ] **Controller + route** — add `drilldown` action to `app/controllers/api/v2/accounts/reports_controller.rb` (401 unless administrator, 422 unless params valid per tasks 1–2, renders builder JSON) and `get :drilldown` on the v2 reports collection in `config/routes.rb`. Port from upstream v4.18.0 (MIT).
6. - [ ] **Rate limit** — add the drilldown throttle to `config/initializers/rack_attack.rb`: key on uid or API access token + account id, default `max(RATE_LIMIT_REPORTS_API_USER_LEVEL / 10, 1)` per minute, env override `RATE_LIMIT_REPORTS_DRILLDOWN_API_USER_LEVEL`. Port from upstream v4.18.0 (MIT).
